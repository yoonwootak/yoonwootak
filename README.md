구현에서 끝나지 않고 테스트와 검증으로 마무리하는 백엔드 개발자를 준비 중입니다.  
Spring Boot 기반으로 백엔드 개발을 학습하고 있습니다.

## 소개

- 오류 없이 안정적으로 동작하는 시스템을 만드는 데 더 큰 가치를 둡니다.
- 맡은 일은 대충 넘기지 않고, 실제로 문제없이 동작하는지 확인할 때까지 검증하려는 편입니다.
- 감으로 진행하기보다 구조와 방법을 먼저 파악하고, 필요한 부분부터 완성해 나가는 방식을 선호합니다.
- 협업에서는 역할과 기준을 먼저 맞춰야 재작업을 줄일 수 있다고 생각합니다.

## 현재 집중하고 있는 것

- 트랜잭션 경계 설정과 동작 원리 이해
- DB 제약 조건을 활용한 데이터 무결성 설계
- 동시 요청 환경에서의 중복 처리 방지

## 기술 스택

### Backend

- Java
- Spring Boot
- Spring Data JPA

### Database

- MySQL

### Testing

- k6

## 프로젝트

### seat-reservation-api

- 티켓팅 흐름을 반영한 좌석 예약 API 개인 프로젝트
- 사용 기술: `Java`, `Spring Boot`, `Spring Data JPA`, `MySQL`, `k6`
- 핵심 기여: 조건부 `UPDATE`와 상태 기반 설계로 동일 좌석에 대한 중복 선점 문제를 개선
- 검증 결과: 동일 좌석 100건 동시 요청에서 `200 성공 1건 / 409 충돌 99건`
- 링크: [GitHub](https://github.com/yoonwootak/seat-reservation-api)

### MUSIM.CO

- AI 운동 자세 교정 웹 서비스를 주제로 한 졸업작품 팀 프로젝트
- 사용 기술: `Python`, `Flask`, `MySQL`
- 역할: 백엔드 개발 담당
- 핵심 기여: 실시간 운동 횟수 측정 API와 사용자 활동 기능 구현, 프론트엔드와 API 구조를 사전 정의해 병렬 개발 방식으로 협업 조정

## 문제 해결 포인트

- 단일 요청에서는 정상 동작하는 구조도 동시 요청 환경에서는 전혀 다른 문제가 발생할 수 있다는 점을 직접 확인했습니다.
- 동시성 문제는 애플리케이션 로직뿐 아니라 DB 설계와 검증 과정까지 함께 봐야 한다고 생각합니다.
- 팀 프로젝트에서는 내 역할을 정확히 해내는 것을 기본으로 하되, 전체 흐름과 협업 기준까지 함께 보는 태도를 중요하게 생각합니다.
